The evaluation method

What it measures, why it is built this way, and the same model runs scored four ways so the differences can be inspected rather than taken on trust. Every figure on this page is computed by build_eval_method.py from the run checkpoints and the ground-truth CSVs.

1. What we are asking of the sources

The Venice 39 material is a weekly register of foreign visitors: each page lists arrivals in the left column and departures in the right, one line per named traveler, with title, dates, lodging and place of origin. Two different historical questions are being put to it, and this experiment is the second half of a two-part study that separates them.

1. How many people are recorded here? A count of unique named travelers per page. This is the question the question-answering half of the study asks directly, and it is answerable without reading a single name correctly.
2. Who were they? The names as written, transcribed faithfully enough to identify individuals, link them across records and search for them.

These are different capabilities and a model can have one without the other. An evaluation that returns a single number cannot tell you which you have. That is the whole design constraint.

2. What the method does

Step 1 — count. Count the distinct named travelers the model reports on a page and compare with the ground-truth count for that page. Duplicated rows collapse to one traveler, because the question is how many people are recorded, not how many rows were emitted. No name matching is involved; a model that invents every name still counts correctly if it reports the right number of people.

Step 2 — align. Pair each model row with the ground-truth traveler it is closest to, order-blind, using character similarity on the name. Before comparing, added titles, articles and places of origin are removed from the model's name field, and the best available reading wins — so Il Barone Bassa is compared as Bassa and Israel Baysan di Verona as Israel Baysan. The unreduced name is always among the candidates, so a reduction can only reveal a name that was buried, never lower a score.

Step 3 — measure transcription. Over the aligned pairs, report character error rate on the name itself: CER = levenshtein(gt, model) / len(gt), micro-averaged, plus the share of names reproduced exactly. The alignment used for this measure has no similarity floor, so a badly read name stays in the pool instead of being dropped for being badly read.

Step 4 — characterise what is left over. Rows with no ground-truth counterpart are classified rather than lumped together: a traveler listed twice, two travelers merged into one row, a fragment of a name, a real traveler misread past recognition, or an invention with no counterpart on the page.

Detection precision and recall are still reported, at a 0.70 similarity threshold, but they are one output among several rather than the headline.

5. Why this rather than the alternatives

A single F1 answers neither question. F1 counts rows that cleared a similarity bar. GPT in the naive condition scores 0.304 under the published method, which reads as a failure to find the travelers. It is not: on page 39 it reports 9–10 unique named travelers against a ground truth of 10, the same count Gemini 3.1 reports, and then misreads them at 0.48 character error against Gemini 3.1's 0.12. The models are equally good at the first question and very unequal at the second. One number cannot say that.

Ratcliff-Obershelp is not an edit distance (M1 → M2). difflib's ratio anchors on the longest matching block and recurses either side, so characters stranded across the anchor cannot be matched, and the result is not interpretable outside the script that computed it. CER is the field standard for transcription, is a true minimum edit distance, and composes: a page's CER is the CER of its concatenated text. The cost of switching is visible in the M1 → M2 column and is large, which is precisely why it should not be left to an incidental choice of library function.

But CER must not be the gate (M2 → M4). Reference-length normalization makes CER asymmetric: appending content to a name is penalised as heavily as getting it wrong, so a model that writes the traveler's origin or title into the name field is recorded as having found nobody. The reductions in M4 remove exactly that, and nothing else — the unreduced reading is always retained, so the change can only recover a name, never inflate one.

Order-preserving alignment costs more than it returns (M3). Requiring the model's row order to follow the ground truth's forfeits matches when a model reads across the two columns instead of finishing the left one first, or groups a family together. Both are legitimate readings of a page the prompt never asked to be traversed in a particular order. Order is worth measuring; it is not worth charging to detection.

The transcription measure must not be conditioned on the match. Reporting CER only over rows that cleared the threshold measures the names a model read well, by construction. Scoring over the complete unthresholded assignment keeps the failures in the denominator: GPT's naive character error is 0.42 measured this way, against 0.16 when computed only over rows that passed the gate.

6. What this method does not do

  • The alignment used for the transcription measure is bookkeeping, not a claim of identity. Pairing a model's row with a ground-truth traveler at 0.30 similarity does not assert they are the same person; it places the row where its character error can be counted. Detection is answered by the counts and the thresholded precision, never by the size of the assignment.
  • CER is a corpus statistic. Over hundreds of names per cell it is stable; on a single short name it is very noisy, which is why no per-name threshold should be read as a confident judgment about that name.
  • It measures names. The other eight fields are scored separately and their normalization rules are still under review.
  • Nothing here evaluates whether a traveler was correctly placed in the arrival or the departure column.
