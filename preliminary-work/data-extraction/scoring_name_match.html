Name matching and field conflation

How a traveler name is scored, why two different similarity measures give different answers, and where models put the right value in the wrong field. Every figure on this page is computed from the run checkpoints and the ground-truth CSVs by build_scoring_doc.py; none of it is typed by hand.

1. What the name score is, and what it is not

The name is the matching key, not a scored field. It never appears in SCORED_FIELDS, so its accuracy contributes to no published figure directly. It enters the results in exactly one way:

1. A similarity is computed for each candidate (model row, GT row) pair.
2. Pairs below 0.7 are rejected; the rest are eligible to match.
3. Rows are paired, and then the similarity value is discarded.
4. Matched rows are counted: precision = matched / rows produced, recall = matched / GT travelers, F1 = 2PR/(P+R).

So a pair at 0.71 and a pair at 1.00 are indistinguishable in every published number, and a pair at 0.69 is counted twice against the model — once as a false positive and once as a missed traveler.

2. The two similarity measures

Published (evaluate.name_similarity) — the larger of two candidates:

  • difflib.SequenceMatcher.ratio(), which is Ratcliff-Obershelp: 2·M / T, where T is the combined length of both strings and M counts characters matched by taking the longest contiguous block and recursing either side of it. It is not an edit distance: characters stranded across an anchor block cannot be matched.
  • token-set overlap, |A∩B| / max(|A|,|B|), requiring whole identical tokens.

CER-based (analyze_name_precision.sim) — 1 − CER, where CER = levenshtein(gt, model) / len(gt), a true minimum edit distance normalized by the reference length. This is the measure already used for the eight scored fields, via evaluate.char_accuracy.

They agree on plain substitutions and diverge on length: the combined-length denominator absorbs appended text, the reference-length denominator does not.

3. Worked cases

name sim columns are computed on the untouched strings. title score and origin score are the scorer's own per-field results for the same row, so a row can show a correct title and a failed name match caused by that same title.

A model that transcribes the line as written produces one row where GT has two or three, so it is charged one false positive plus a missed traveler for each name it did in fact read.
