Equivalences and ignore rules

This file is the input to the scorer, not a description of it. rules.py reads it and evaluate.py applies it, so a row here changes how runs are scored.

Every row is applied: there is no draft state.

The side column applies to §1 and §2 alike: both normalizes ground truth and model output together; model applies only to model output, for things the ground truth never contains.

Every form must have a witness in the transcription or the ground truth. python check_equivalences.py reports load-bearing vs redundant rows, unobserved forms, any ignore-token that collides with a GT name, and §3 rows or alternatives that are dead or redundant.

1. Ignore — remove this token, then compare

The value is compared with the token removed. For name, the unreduced form is always kept as a candidate and the better reading wins, so an ignore rule there can only reveal a name that was buried, never lower a score.

Always name the field: Cormos is a place in place_of_origin and part of a name in name. Several fields can share one row.

position decides where the token has to sit, and how much goes with it:

positionremoves
leadingthe token, at the start of the value only
trailingthe token, at the end of the value only
anywherethe token, wherever it occurs
onwardthe token and everything after it — for a trailing clause such as an appended place of origin

di at the start of a name is a connective; di in the middle is part of Ernesto di Bargh. That is why position is stated rather than inferred. No rule empties a value: if the token is all that remains, it stays.

3. Dictionary of acceptable alternatives

This section defines what counts as correct. title, arrival_date, departure_date, place_of_stay and place_of_origin are scored right or wrong: after §1 and §2 have run, a model value either equals the ground truth or appears on that ground truth's row here. Nothing else is credited. name is out of scope — it pairs model rows to ground-truth rows rather than being checked for correctness, and keeps similarity scoring throughout.

Write normalized forms, not raw data. Both sides are compared after the normalizers and the §1/§2 rules have run — lowercase, abbreviations folded to their canonical (s. → san, loc: → locanda, q.m → quondam), commas and colons gone. The loader runs every entry through the same pipeline, so a raw form still matches, but it may not land where it reads as if it does: s. [san] vido below is stored as san [san vido. Writing the normalized form keeps the table saying what the scorer does. python check_equivalences.py prints every entry as normalized, and flags a dead row (ground truth not a normalized GT value), a dead alternative (no model output reaches it) and a redundant one (§1/§2 already make it equal). To check what a form normalizes to before entering it: python -c "import evaluate as e; print(e.norm_place('YOUR VALUE', False, field='place_of_stay'))" — normalization is idempotent, so a value that comes back unchanged is safe to enter.

One row per ground-truth value, with the alternatives separated by =, the same syntax §2 uses. The ground-truth column takes a single normalized value.

Prefer §2 when the variation is token-level: a rule there generalizes to every value containing the token, while an entry here authorizes one form for one ground truth. de'poveri for de' poveri is token-level and belongs in §2; casa di pietro danna locandiere a san giovanni grisostomo is a one-off phrasing and belongs here.
